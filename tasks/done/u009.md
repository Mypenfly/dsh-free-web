## 坑

- `plainSchema()` 会**删掉** `meta.volatile`，所以 `describe()` 返回的 `schema` 里看不到 volatile 标记；
  判断「这个字段可编辑」只能靠「它出现在 form 里」+「写它不被 `isVolatilePath` 拒」。
- `--patch` CLI overlay 只要碰了某个 entry 的 config，`settings.mutate` 就会以
  `Configuration for "X" is overridden by a home patch or command-line overlay` 拒绝——
  验证写回必须把初始值放进 profile 的 `cordis.patch.yml`，overlay 只用来 insert 探针行。
- cordis 的 patch 写盘会 reconcile 整棵树；**探针行自己**在 overlay 里，写入后它的 fiber 会被
  dispose，于是最后一次 `ctx.settings.*` 会抛 `cannot get required service … in inactive context`。
  这不是被测链路失败——把「打印路径/文件内容」放在 dispose 之前即可。
- `@deepseek-ai/schemastery` 是公开 npm 包（`3.19.0`），`link:` 插件也能用：包在自己的
  `node_modules` 里有一份真实副本，Node 从 realpath 往上找得到。跨副本互操作是安全的——
  cosmokit 的 `isVolatile()` 用 `Symbol.for("cosmokit.volatile.write")` 判协议。
- `dsh-client-modules` 用 `<script src>` 装客户端包，`import` 语句直接 SyntaxError，行被判
  `loaded without registering "<id>"`；注册 id 必须等于包名，`platform` 必须精确 `'web'`。
