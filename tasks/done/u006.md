## 坑
- Node `http.request` 被 `signal` 中止时抛的是 `AbortError`（`code:'ABORT_ERR'`）不是 `DOMException`；只认 `instanceof DOMException` 会把超时/取消当成网络错误
- 直连要传 `lookup` 时必须同时处理 `(host, opts, cb)` 的两种形状：`opts.all===true` 要回数组，否则 Node 22 的 autoSelectFamily 拿到 `undefined` 直接崩
- `no_proxy` 的 `a.b.c.d/16` 会先被「去 URL path」的 `replace(/\/.*$/)` 吃掉 → CIDR 必须在 strip path 之前判
- 不要给 `https.request` 传 `socket:` 已建好的 TLS socket（会被再包一层 TLS）；正确姿势是 `https.Agent` 子类 `createConnection(){return tlsSocket}`
- undici 的 `response.text()` 忽略 charset，自建传输按 `content-type` 解码 → GBK 页面中文变好（副作用，不是回归）
- 本机没有 openssl、python 也没有 cryptography → 离线起不了 TLS server，CONNECT 只测到「请求行 + 407 透出」，TLS-over-tunnel 由活网 smoke 覆盖
- 传输层不再受 `NODE_USE_ENV_PROXY` 影响：proxy 只从 `http_proxy`/`https_proxy`/`all_proxy` 读；`proxy: null` 是「强制直连」的显式开关（测试与调试用）
